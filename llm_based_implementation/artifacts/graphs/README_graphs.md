# Feasibility graphs — ProductType classification (5 local models)

Generated by `scripts/make_graphs.py` from `artifacts/model_comparison_*.json`.
Same 100 real eParts products for every model; shortlist=12, temp=0, seed=42.
All models Q4_K_M quantized, served by Ollama on one laptop.

Underlying data:

| Model | Params | Tokens/item | Overall acc. | Confidence acc.¹ |
|---|---|---|---|---|
| llama3.2:3b | 3B | 332.4 | 58.0% | 69.3% |
| qwen2.5:7b | 7B | 324.0 | 64.0% | 69.4% |
| llama3.1:8b | 8B | 326.1 | 67.0% | 71.1% |
| phi4 | 14B | 324.8 | 68.0% | 77.3% |
| qwen2.5:14b | 14B | 324.3 | 63.0% | 66.0% |

¹ Confidence accuracy = % correct among predictions the model asserted at confidence = 1.00.
Perfect calibration would be 100%; the gap below 100% is the over-confidence problem.

## The four graphs

1. **`1_accuracy_vs_tokens.png`** — Overall accuracy vs avg tokens per classification.
2. **`2_accuracy_vs_size.png`** — Overall accuracy vs model size (parameters).
3. **`3_confidence_accuracy_vs_size.png`** — Confidence accuracy vs model size.
4. **`4_confidence_accuracy_vs_tokens.png`** — Confidence accuracy vs avg tokens per classification.

## How to read them

- **Token usage is essentially constant (~324–332 tokens/item) across all models.**
  This is expected: the grounding prompt and the tiny JSON output are the same regardless
  of model, so the structured-classification task costs roughly the same tokens per query
  everywhere. Consequence: the two "vs token usage" charts (1 and 4) have a very narrow
  x-axis — **per-query token cost is NOT a differentiator between these models.** Real cost
  differences come from per-token *pricing* (which scales with model size / hosting), not
  from token *volume*. (Note llama3.2:3b uses slightly more tokens — a tokenizer artifact.)

- **Accuracy rises only modestly with size, and non-monotonically** (graph 2): 58% → 68%
  from 3B to 14B, but the largest model (qwen2.5:14b) dips to 63%. Bigger ≠ reliably better.

- **No model is well-calibrated** (graphs 3 & 4): even the best (phi4, 77%) is wrong ~1 in 4
  times when it claims full confidence; qwen2.5:14b is the worst at 66%. All sit far below
  the 100% line. This is why verbalized confidence cannot drive the ≥ 0.95 auto-process gate.

## Caveats

- n=100 → roughly ±5–9% sampling error per point; the 63–68% cluster is within noise.
- Q4_K_M quantization; full-precision weights may score slightly higher.
- "Confidence accuracy" is a coarse calibration proxy; a full reliability diagram / ECE
  (plan L3) is the rigorous version and the recommended next artifact.
